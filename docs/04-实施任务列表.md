### 1.2 状态和完成规则

每项任务的标题复选框是完成状态的唯一来源；任务下的“状态”用于记录未完成原因：

| 状态 | 含义 | 复选框 |
|---|---|---|
| 待开始 | 尚未实施 | `[ ]` |
| 进行中 | 已开始修改或验证 | `[ ]` |
| 待验证 | 实现完成，但所需证据不足 | `[ ]` |
| 阻塞 | 必要输入或环境不可用，写明原因与解除条件 | `[ ]` |
| 完成 | 实现、调用者迁移及本任务验收均完成，有证据 | `[x]` |

规则：

1. 开始任务前填写负责人；每个工作分支/执行者同时只认领一个主要任务。
2. 依赖未满足时，不把依赖接口当成现有实现。可提前写草稿，但不能勾选完成。
3. 模拟协议、真实 CLI、真实模型服务、实际 UI 是不同证据层级，不能互相替代。
4. 任务验收写明需要哪一层；不要求每个内部模块都启动真实模型。
5. 错误输出和失败观察保留为证据，不靠重复运行掩盖。修复后记录新的验证结果。
6. 标记完成时，将“证据：未记录”替换为实际记录/链接；写清命令、退出码、断言或观察结果。
7. 不通过空实现、默认成功、静默换 Agent/模型、丢弃附件、禁用测试来完成任务。
8. 本文不批准删减范围。确需变更，先明确变更原因、影响和用户决定，再同步设计。

### 1.3 证据格式

每项可以直接填写摘要；输出较长时放在同目录下按任务 ID 命名的证据文件中，再填写相对链接。证据文件是实施时创建的产物，本列表不预先伪造文件。

```text
任务：P3-02
实际改动：文件、关键符号、调用者
验证日期/环境：操作系统、工具链、引擎包与版本、隔离配置
验证命令：实际执行的命令
结果：退出码、关键断言或用户可见观察
证据层级：单元 / 假协议 / 真实 CLI / 真实上游 / 实际 UI
未验证与风险：明确列出，没有则写“无”
关联：提交/PR（如有）、日志或截图的相对路径
```

严禁记录 API Key、敏感 Header、Gateway token、完整用户 prompt 或未脱敏 stderr。

## 2. 阶段与跟进方式

### 2.1 阶段索引

| 阶段 | 任务范围 | 数量 | 阶段出口 |
|---|---|---:|---|
| P0 基线核对 | P0-01～P0-03 | 3 | 当前源码、引擎协议和接口落点可核验 |
| P1 数据与服务 | P1-01～P1-06 | 6 | 数据与凭据可安全保存、恢复，旧模型引用可读 |
| P2 生命周期与契约 | P2-01～P2-05 | 5 | 新接口贯穿调用者，运行与历史生命周期有界 |
| P3 三类后端 | P3-01～P3-06 | 6 | 各后端 Native 协议接入并有真实 CLI 证据 |
| P4 路由与投影 | P4-01～P4-06 | 6 | 自定义服务、三协议和两种轮询方式可用 |
| P5 用户界面 | P5-01～P5-05 | 5 | 从模型服务设置到聊天使用形成 UI 闭环 |
| P6 集成与交付 | P6-01～P6-05 | 5 | 安全、回归、真实服务与 UI 验收有完整证据 |

阶段不另设复选框，避免与任务状态形成两份进度。阶段内所有任务完成才达到该阶段出口；最终交付还必须通过 P6。

### 2.2 默认执行顺序

推荐顺序：P0 → P1 → P2 → P3 → P4 → P5 → P6。允许依赖明确的内部并行：

- P1-01 公共类型确定后，存储侧与 Harness 契约侧可以分工；共享类型由同一集成者维护。
- P3-01 公共协议设施完成后，Pi 与 DSH 适配可并行；OMP 依赖 Pi/OMP 共用消息映射契约。
- Provider 探测与 Gateway 核心可由不同执行者负责，但共享 router/types 只能有一个集成所有者。
- `session.rs`、`proto.rs`、`types.rs`、根 Cargo 配置、settings schema、共享本地化文件不能无约束并行修改。

并行不是跳过验收：每个任务仍要完成其依赖、调用方和验证。涉及全局签名变化的一组修改必须一次完整集成，不提交缺失分支或残留旧 API。

### 2.3 每次跟进需要回答

1. 当前任务 ID、负责人和状态是什么？
2. 本次完成了哪个可观察行为，证据在哪里？
3. 未完成的是代码、协议适配、外部环境还是验证？
4. 阻塞影响哪些后继任务，解除条件是什么？
5. 下一项已满足依赖的任务是什么？
