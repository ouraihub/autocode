# P1-06 证据：聊天模型身份与旧数据读取迁移

- 日期：2026-11-18
- 执行者：autocode（Claude Code）
- 状态：**完成**

## 变更

- `agent_chat/src/session.rs`：`RunSettings.model` 从 `Option<String>` 迁移为 `Option<ModelSelection>`。
- 兼容读取边界：旧 JSON 字符串自动转为 `ModelSelection::Native { id }`。
- 新 JSON 一律写 tagged object：
  - Native：`{"source":"native","id":"..."}`
  - Managed：`{"source":"managed","provider_id":"...","model_id":"..."}`
- 缺少 `config_source` 默认 `ConfigSource::Native`。
- 损坏的对象通过 serde 错误返回，不能静默清空为 `None`。
- 添加 `RunSettings::native_model()` / `native_model_id()`，仅在 Harness wire 边界将 Native 身份还原为 `Option<String>`。
- Provider/model 结构化身份不会被 UI picker 拆成字符串；旧 Native picker 只消费 `native_model()`。
- model picker、chat view、reasoning helper、RunRequest 构造、session 测试全部同步迁移。
- 移除 P1-04 遗留的 `CredentialMetadataRepo` alias，所有实现统一使用 `ProviderRepository`。

## 保持的兼容边界

`RunRequest.model` 仍保持 `Option<String>`，因为它是现有 Claude/Codex/OpenCode Harness wire 合同。Managed 模型暂不直接送入旧 Harness；其 provider/model 身份保留在结构化 `ModelSelection` 中，后续 P2 routing 层负责解析。
