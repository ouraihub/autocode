## 构建环境阻塞（本机）

- 本机 **未安装 MSVC Visual Studio Build Tools**。
  - `VSINSTALLDIR` / `VCINSTALLDIR` 为空。
  - `C:/Program Files/Microsoft Visual Studio/2022` 不存在。
  - PATH 中的 `link.exe` 解析到 `D:/Program Files/Git/usr/bin/link.exe`（Git-for-Windows 自带的 GNU `link`，功能是创建硬链接，**不是链接器**）。
- 后果：rust 1.97.1 的 `x86_64-pc-windows-msvc` target 无法链接任何 build script，在 `cargo check -p db`（后台任务 bg_3，耗时 381 秒）时首个用到 build script 的 crate 失败：
  ```text
  error: linking with `link.exe` failed: exit code: 1
  = note: link: extra operand '…serde_core.build_script_build…cgu.00.rcgu.o'
          Try 'link --help' for more information.
  note: you may need to install Visual Studio build tools with the "C++ build tools" workload
  ```
- 解除条件（**必须完成才能运行 cargo**）：
  - 安装 Visual Studio Build Tools 2022 并勾选 "Desktop development with C++"（至少 MSVC v143、Windows SDK、CMake）。
  - 新 shell 内 `where link.exe` 第一个命中必须位于 `…/VC/Tools/MSVC/*/bin/Hostx64/x64/link.exe`。
- 影响范围：本会话无法编译、测试或运行任何 crate；`./script/clippy` / `cargo check` / `cargo test` / `cargo run -p wu` 全部受阻。P1 及以后的任务代码可以编写，但"完成条件"中需要 `cargo` 产出的证据需在环境修复后补齐。

## 本会话尝试过的规避路径（均失败）

1. `cargo check -p model_provider --target x86_64-pc-windows-gnu`：bg_1。
   - build script 仍在 host triple（x86_64-pc-windows-msvc）下编译，仍用 PATH 的 GNU `link.exe`，仍失败。
   - 且 1.97.1 未装 `x86_64-pc-windows-gnu` rust-std，`rustup target add x86_64-pc-windows-gnu --toolchain 1.97.1-x86_64-pc-windows-msvc` 没装过。
2. `CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_LINKER=…/rust-lld.exe LIB=zig-cache-dir cargo check -p model_provider`：bg_2。
   - rust-lld 成功替代 GNU link；但 `/defaultlib:libcmt` 要求 MSVC CRT 完整 import libs（`kernel32.lib`、`ntdll.lib`、`userenv.lib`、`ws2_32.lib`、`dbghelp.lib`、`libcmt.lib` …），zig 只按需生成 `kernel32.lib`。
   - scoop LLVM、scoop mingw-mstorsjo-llvm-msvcrt 均不提供 MSVC `libcmt.lib`。

结论：Rust `x86_64-pc-windows-msvc` target 必须要 MSVC CRT 与 Windows SDK import libs；无 Visual Studio Build Tools 时本工程无法构建。安装 "Desktop development with C++" 是硬门槛。
