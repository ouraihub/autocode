## 本任务范围

实施 `docs/03-详细设计.md` §5.1、§5.2：

- 7 张表的 `Domain` 迁移（`agent_chat::provider_store::ProviderDb`）。
- 只做 SQL 的 CRUD：provider / endpoint / model 注册，key / header 元数据，`model_credential_ops` 日志，`agent_launch_preferences` 加载与保存。
- `revision` 乐观并发：`UPDATE revision = revision + 1 WHERE id=? AND revision=?`；0 行变化区分 `NotFound` / `Conflict`。
- 级联删除时登记 `pending_delete`；commit_key / commit_header 替换时自动把旧 `credential_ref` 加入 `pending_delete`。
- 不访问系统凭据：调用方（P1-03 broker + P1-04 service）持有 `CredentialStore`，本层只接受已经写入凭据后的 `credential_ref`。

## 契约要点

- **revision 事务**：每个写事务第一步调用 `bump_revision`；返回 Ok 后再做依赖写入；`SAVEPOINT provider_*` 保证子操作失败回滚。
- **行级 vs JSON 偏好 revision**：`load_preferences` 读取行级 revision 覆盖 JSON 内的 `revision` 字段，避免 JSON 自说自话；`save_preferences(expect=0)` 只允许 INSERT，其他值要求 UPDATE 命中。
