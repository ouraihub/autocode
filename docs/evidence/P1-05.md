## 契约

- `ProviderRepository` 统一承载 Provider CRUD、凭据元数据、偏好；旧 `CredentialMetadataRepo` 保留临时类型别名，避免 P1-04 调用方断裂。
- 所有 CRUD/Key/Header/偏好写操作在底层 SQL 成功后才发送 `ProviderChange`。
- `ProviderChange` 只携带 `kind`、provider_id、target、revision，不携带 Secret、Secret 明文或模型正文。
- 广播是有界信号，不是事件日志；慢消费者可丢事件，必须重新读取快照。
- `delete_provider` 保留已删除 provider ID 的 `Deleted` 事件，revision 为 0，缓存可以按 ID 无条件失效。
- `reveal_key` / `reveal_header` 是显式操作，常规快照始终只返回 `credential_ref` 和 masked 值。
- `AgentPreferences` 通过 repository 的 expect revision 保存；保存成功后才广播 backend-scoped event。
- `ProviderServices` 存在于单个 GPUI App Global，不使用 process static singleton；pump Task 由 Global 持有，Global drop 时 broker 停止。
- `agent_chat::init` 启动 reconcile；失败只记录结构化 target 日志并留待下次启动，不回退明文数据库。
